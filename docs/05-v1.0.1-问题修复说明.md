# v1.0.1 修复说明：语音链路与视觉重做

> 版本：1.0.1（versionCode 2）｜基于真机反馈的两处问题
> 产物：`dist/SuiJi-v1.0.1-release.apk`

---

## 一、语音：点「说话」没反应、录不了、转不出字

### 1.1 现象

点击录入页的麦克风按钮后：没有录音状态、没有波形、没有文字，多数情况下界面毫无变化；个别机型弹一次权限框后依然没有下文。

### 1.2 根因（四个叠加，缺一不可）

**根因 A：整条语音链路只依赖系统 `SpeechRecognizer`。**

v1.0.0 的 `SpeechHelper` 直接用 `SpeechRecognizer.createSpeechRecognizer()` + `ACTION_RECOGNIZE_SPEECH`。这要求手机里存在一个实现了 `android.speech.RecognitionService` 的应用。国产 ROM 的现实是：

| 情况 | 结果 |
|---|---|
| 未安装 Google / 未装语音服务 | `isRecognitionAvailable()` 返回 false |
| 只保留自家语音助手（Jovi、小爱等），未暴露标准接口 | 同上 |
| 有服务但需要联网、账号或首次授权 | `startListening` 后回 `ERROR_CLIENT` / `ERROR_NETWORK` |

本次排查在 API 34 模拟器上取了实证：

```
$ adb shell pm list packages | grep -i speech
（无输出）
$ adb shell dumpsys package | grep -A2 'android.speech.RecognitionService'
queriesIntents=[Intent { act=android.speech.RecognitionService }]   ← 只有我们自己声明的 queries
```

即整机没有任何 RecognitionService。代码走到 `if (!available()) { onError(SttUnavailable); return }` 就直接返回了 —— 表现出来就是「按了没反应」。**这是设计缺陷：把「能不能录音」这件事交给了厂商是否预装某个服务。**

**根因 B：首次点击只申请权限，授权后不会自动开录。**

原逻辑：

```kotlin
if (!hasMicPermission) { onRequestMic(); return@clickable }   // 弹框，然后什么也不做
```

用户在权限框点了「允许」回到页面，看到的还是同一个静止界面，必须再点第二次。多数人第一次就判定「坏了」。

**根因 C：没有任何录音状态的实时反馈。**

- `onRmsChanged(rmsdB)` 是空实现 —— 麦克风真实的音量数据被丢弃
- 界面的 `Waveform()` 是写死的 7 根固定高度柱子，不是波形，是装饰
- 没有计时器，没有「正在录音」的明确状态
- 即使真的在录，用户也完全感知不到

**根因 D：错误被过度归并，掩盖了真实原因。**

`ERROR_CLIENT`、`ERROR_SERVER`、`ERROR_AUDIO` 全部落到 `AppError.EmptySpeech`「没听清，再说一次」。用户以为是环境吵或自己没说清楚，实际是服务不存在/被占用。

### 1.3 修复方案

核心思路：**把「录音」和「转文字」拆成两件独立的事，录音用绝不依赖厂商的通道保底，转写走双通道。**

#### （1）新增本地录音器 `voice/VoiceRecorder.kt`

- `AudioRecord`，16 kHz / 单声道 / 16-bit PCM，音源优先 `VOICE_RECOGNITION`（不做 AGC，更适合 ASR），失败回落 `MIC`
- 分块读 100 ms，实时算 RMS → 归一化成 0..1 的音量，通过回调抛给 UI
- 落盘 `.pcm`，停止时补 44 字节 WAV 头转成标准 `.wav`（可直接喂给任何 ASR）
- 600 ms 以下视为误触；120 s 自动截断；`startRecording` 后校验 `recordingState`，不通过就报 `RecordFailed`
- 只依赖 `RECORD_AUDIO` 权限。**这一条保证了「点击一定能录」，与机型无关。**

#### （2）新增转写客户端 `voice/AsrClient.kt`

- OpenAI 兼容协议：`POST {base}/audio/transcriptions`，`multipart/form-data`
- 手工拼 multipart（`file` / `model` / `language` / `response_format`），零第三方依赖
- 复用用户已填的那把 Key；地址默认跟随 AI 接口地址，可单独覆盖
- HTTP 状态码映射到既有错误体系（401 / 402 / 404 / 429 / 5xx）

#### （3）新增编排器 `voice/VoiceController.kt`

一个状态机 + 两条通道：

| 通道 | 触发条件 | 特点 |
|---|---|---|
| SYSTEM | 自动模式下 `isRecognitionAvailable()` 为真，或用户强制选「系统」 | 边说边出字，零配置 |
| LOCAL | 系统不可用，或用户强制选「云端」 | 本地录完再上传转写，波形/计时来自真实音量 |

细节处理：

- **自动续听**：系统通道下遇到 `ERROR_NO_MATCH` / `ERROR_SPEECH_TIMEOUT`，只要用户没主动停，就重建 recognizer 继续听，不会因为停顿一下就把会话掐断
- **停止兜底**：`stopListening()` 在部分 ROM 上不回调，4 秒超时后按已收到的 partial 收尾
- **录到了但转不了**：本地录音成功、但没有 Key 时，把 WAV 挂在 `pendingAudio` 上，界面给「重试转写」；用户去设置填好 Key 回来一键重试，不用重新说一遍
- 所有 `SpeechRecognizer` 的创建/销毁/`startListening` 都在主线程，避免 `ERROR_CLIENT`

#### （4）重写录入页的录音 UI

- 真实波形：32 根柱子，由 RMS 驱动，无输入时是平滑的小点，说话时起伏
- 真实计时：`0:03` 逐秒推进
- 呼吸圆环：外圈随音量扩张，中央麦克风图标压在上面
- 状态文案分三段：`正在录音…` / `正在听…` / `正在转成文字…`
- 按钮三态：麦克风 → 停止方块（红色）→ 转圈（转写中）
- 首次点按无权限：`autoStart = true` → 弹权限 → `LaunchedEffect(hasMicPermission)` 检测到授权后**自动开录**，不需要第二次点击

#### （5）错误码补齐

新增 `RecordFailed(2009)`、`AsrNotConfigured(2010)`，并改写既有三条文案，让提示可执行：

| 场景 | 提示 |
|---|---|
| 无麦克风权限 | 未授权麦克风，可用文字录入 · 点这里重新授权 |
| 麦克风被占 | 麦克风被占用 · 关掉通话或其他录音应用再试 |
| 系统无识别且未配 Key | 录到了，但还没有转写通道 · 去设置里填 Key 并开启「云端识别」 |
| 本机无识别服务 | 本机没有语音识别服务 · 去设置里开启「云端识别」，或直接打字 |

#### （6）设置页新增「语音转文字」分组

- 识别方式：自动 / 系统 / 云端
- 转写模型：默认取服务商预设（OpenAI → `whisper-1`，硅基流动 → `FunAudioLLM/SenseVoiceSmall`，其余留空可手填）
- 转写地址：留空则跟随 AI 接口地址
- 就绪状态：绿点「转写通道就绪」/ 红点「未就绪」+ 具体缺什么

### 1.4 验证记录

| 项 | 方法 | 结果 |
|---|---|---|
| 录音启动 | 无 Key、无系统识别环境下点麦克风 | 进入录音态，计时 0:03 → 0:05 正常推进 |
| 音频采集 | mock 服务记录请求体 | `ASR bytes=688149 multipart=True wav=True model=whisper-1`（约 21 秒 16k 单声道 PCM，大小与时长吻合） |
| 转写回填 | mock 返回 `{"text": ...}` | 文本框自动出现「下周三下午三点和张总过报价单」，「收好」按钮由灰转亮 |
| 连续录入 | 再录一段 | 文本累加，不覆盖 |
| 无 Key 降级 | 清空 Key 后录音 | 正常录完，提示「录到了，但还没有转写通道」，带「重试转写」「去设置」 |
| 无权限 | 撤销 RECORD_AUDIO | 弹系统权限框；授权后自动开录 |

> 说明：模拟器无麦克风输入，波形为静音态（平滑小点）属预期；真机说话时会随音量起伏。

## 二、界面：简陋、层级糊、不专业

### 2.1 根因

v1.0.0 的界面不是「设计得不好」，而是**根本没有设计系统**：

1. **没有设计令牌**：颜色散落在各处 `Color(0xFF2E7D32)`、`Color(0xFFC62828)` 直接写死；字号 11/12/13/14/15/16/18/20/22/24 sp 随手取；圆角 4/6/8/10/12/16 混用。
2. **没有视觉层级**：标题 22sp、正文 16sp、注释 12sp，差距不足以形成阅读顺序；卡片只有一圈 1 dp 细边，没有投影，和背景糊在一起。
3. **没有图标系统**：按钮上写的是汉字「说」「停」，空状态只有两行字，没有图形；唯一像图标的地方是「›」和「←」。
4. **布局没有节奏**：所有区块都靠 `Spacer(8.dp)` 硬撑，横向 16/20 dp 混用，信息密度忽高忽低。
5. **两个技术性问题**：内容没有做状态栏内边距（真机会被状态栏压住）；系统返回键直接退出 Activity，而不是退出覆盖层。

### 2.2 修复方案

#### （1）建立设计令牌 `ui/Theme.kt`

| 维度 | 取值 |
|---|---|
| 底色 | 纸感暖白 `#F7F6F2`（不是纯白，长时间看不刺眼） |
| 主色 | 墨绿 `#15564A`，容器色 `#DCE9E3` |
| 点缀 | 陶土 `#9C5B2E`（灵感类） |
| 语义色 | `SuiExtra(todo / idea / unclassified / success / danger)`，通过 `CompositionLocal` 下发，亮暗两套 |
| 字号 | display 30 / headline 24 / title 20 / titleMedium 16 / body 15 / bodySmall 12.5 / label 10.5，**带负字距的标题** |
| 圆角 | 8 / 12 / 16 / 22 / 28 五档 |
| 行高 | 正文 25sp，保证中文不挤 |

#### （2）图标全部用 Canvas 现画 `ui/Icons.kt`

不引 `material-icons-extended`（会给 APK 加 1~2 MB），也不塞几十个 vector 资源。统一用 `drawLine / drawCircle / drawRoundRect / drawPath` 画：麦克风、搜索、设置（三条滑杆）、勾选、时钟、灵感星、垃圾桶、返回、关闭、停止、右箭头，外加一张空状态插画（叠纸 + 落笔点）。全部走 `LocalContentColor`，尺寸与线宽等比自适应。

> 设置图标最初画的是齿轮，缩到 17 dp 时齿和圈糊成一个「太阳」，改为三条滑杆后辨识度明显更好。

#### （3）重建组件体系 `ui/Components.kt`

- `MemoCard`：18 dp 圆角 + 1 dp 阴影像素级投影 + **左侧 3 dp 类型色条**（待办绿 / 灵感陶土 / 过期红）+ 圆角勾选圈（勾上时填充并出现对勾）
- `SectionHeader`：日期 + 圆点 + 细分割线 + 右侧计数，替代原来的「今天 · 1」
- `PrimaryButton / GhostButton`：主次分明，主按钮带 6 dp 同色投影
- `SearchField`：常驻搜索框（原来是个 150 dp 的小输入框挤在筛选按钮后面）
- `EmptyState` + `EmptyIllustration`：有插画、有主副文案、可只显示文字版
- `PressableBox`：统一按压反馈

#### （4）首页与详情重排 `ui/HomeScreen.kt`

- 标题区：26 sp「随记」+ 一句动态副标题（`今天 · 共 1 条`），设置按钮收成 38 dp 圆钮
- 筛选：三个 11 dp 圆角 chip，选中态实心，未选态描边（原先是同样大小的灰底胶囊）
- 卡片：标题 15.5 sp 两行截断，元信息行前置时钟/星形图标，`张总` 这类对象做成独立小标签
- 双栏模式：左列表右侧详情，空列表时左栏只留文字、右栏放插画，避免同一屏两个插画
- 详情：类型 chip + 时间 → 24 sp 标题 → 引擎与置信度 → 正文卡片 → 次级操作按钮 → AI 深化区块（主色容器 + 星标）

#### （5）录音页 `ui/CaptureScreen.kt`

见第一章第（4）点，不再重复。

#### （6）设置页 `ui/SettingsScreen.kt`

从「一条条平铺的 Row」改为**分组卡片**：AI 模型 / 语音转文字 / 柔性提醒 / 权限与后台 / 关于，每组 18 dp 圆角卡 + 组内细分隔线 + 组间 22 dp 留白。密码框、按钮、开关、滑杆统一样式。

#### （7）工程性修复

- `AppRoot` 加 `systemBarsPadding()`，内容不再被状态栏/导航栏压住
- 主题色改为新底色，`windowLightStatusBar=true`，状态栏图标在浅色底上可见
- 加 `BackHandler`：返回键按 `AI 深化 → 记录 → 设置 → 详情 → 退出` 的顺序逐层退，不再一按就杀 Activity

## 四、已知限制

1. **真机未复验**：本轮验证仍在 API 34 模拟器完成。模拟器无麦克风输入，波形只能验证到「静音态」；vivo X Fold3 上的实际音量起伏需真机确认。
2. **云端转写依赖服务商支持**：DeepSeek / 智谱 / 通义 / Kimi / 火山 / 千帆 / MiniMax 目前未提供 OpenAI 兼容的 `/audio/transcriptions`，这些服务商下需把「语音转文字」指向硅基流动或 OpenAI，或手填地址。系统识别可用的机型不受影响。
3. **音频上传与隐私**：选择云端识别时录音会上传用于转写，拿到结果后立即删除本地文件；选择系统识别则音频不出本机。设置页「关于」已如实写明。
