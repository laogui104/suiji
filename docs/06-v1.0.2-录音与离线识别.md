## 一、为什么"接入了大模型"还是转不了文字

这是这次最核心的一条，也是我之前没说透的地方。

### 1. 对话模型 ≠ 语音转写模型

语音转文字走的是 OpenAI 协议里**另一个接口**：

```
POST {base_url}/audio/transcriptions
```

它和聊天用的 `POST {base_url}/chat/completions` 是两套东西。你接入的 DeepSeek / 智谱 / 通义 / Kimi / 火山 / 千帆 / MiniMax，
**都没有这个接口** —— 它们只做文本对话，不接音频。

v1.0.1 的代码逻辑是：

```kotlin
// 旧版：只要填了 Key 且模型名非空，就当云端转写可用
fun asrReady() = !apiKey().isNullOrBlank() && effectiveAsrModel().isNotBlank()
```

把 DeepSeek 的地址填进「转写地址」，再给个模型名，程序就真的往
`https://api.deepseek.com/v1/audio/transcriptions` 发请求 —— 必然 404。
用户看到的现象就是：**大模型明明连上了、能分拣能总结，就是转不了文字。**

### 2. 修法：不再赌云端，把识别能力装进 APK

新增 **内置离线识别**（`voice/OfflineAsr.kt`）：

| 项 | 值 |
|---|---|
| 引擎 | Vosk 0.3.47（native，无 Java 层依赖） |
| 模型 | `vosk-model-small-cn-0.22`，中文，42 MB |
| 打包方式 | 放在 `assets/model-cn.zip`，随 APK 分发 |
| 首次使用 | 解压到 `filesDir/asr-model/`，约 10 秒，只需一次 |
| 联网 | **不需要** |
| API Key | **不需要** |
| 机型依赖 | **没有**（纯本地 so + 模型） |

转写路由改成三级：

```
① 云端（仅当服务商真的有 /audio/transcriptions）
      ↓ 失败 / 不可用
② 内置离线识别  ← 永远可用
      ↓
③ 仍失败 → 保留音频，界面给「重试」
```

判断"云端到底行不行"的逻辑（`Settings.cloudAsrUsable()`）：

```kotlin
fun cloudAsrUsable(): Boolean {
    if (asrMode == ASR_OFFLINE) return false
    if (apiKey().isNullOrBlank()) return false
    if (effectiveAsrBaseUrl().isBlank()) return false
    if (effectiveAsrModel().isBlank()) return false
    // 必须是「该服务商自带转写能力」或「用户单独指定了转写地址」
    val dedicated = asrBaseUrl.trim().isNotBlank()
    val providerCapable = provider().asrModel.isNotBlank()
    return dedicated || providerCapable
}
```

DeepSeek 用户 → `providerCapable=false`、`dedicated=false` → 直接走离线，**不会再发那个注定 404 的请求**。

### 3. 实测证据（不是推测）

我用 edge-tts 合成了一段中文语音「明天下午三点和张总过报价单」，
转成 16kHz / 单声道 / 16bit —— 和 App 里 `VoiceRecorder` 产出的格式完全一致，
然后在模拟器上跑 instrumented test，直接喂给 `OfflineAsr`：

```kotlin
// app/src/androidTest/java/com/suiji/assistant/OfflineAsrTest.kt
val result = OfflineAsr.transcribe(ctx, wav)
println("ASR_RESULT = $result")
```

真实输出：

```
I System.out: ASR_RESULT = Ok(data=明天下午三点和张总过报价单)
I System.out: ASR_TEXT   = 明天下午三点和张总过报价单
```

**一字不差。** 全程没联网，没配任何 Key。测试通过（7.5 秒，含首次解压模型）。

设备上的模型加载日志也确认解压路径正确：

```
I VoskAPI : ReadDataFiles():model.cc:249) Loading i-vector extractor from
            /data/user/0/com.suiji.assistant/files/asr-model/vosk-model-small-cn-0.22/ivector/final.ie
```

### 4. 顺带修掉的一个真 bug

设置页「识别方式」的 chip 点了不刷新 —— `setAsrMode()` 只写了 SharedPreferences，
UI 读的是普通函数，Compose 不会重组。现在改成状态变量：

```kotlin
var asrModeState by mutableStateOf(settings.asrMode)
    private set

fun setAsrMode(m: String) {
    settings.asrMode = m
    asrModeState = m
}
```

## 二、录音按钮：做大、搬到首页、去掉读秒

### 改动前

- 按钮 56dp，**藏在二级页面**，首页只有一个「说一句」胶囊，点了要跳转
- 录音页中间显示 `0:03` 这种跳秒数字

### 改动后（`ui/VoiceBar.kt`）

首页底部常驻一个 **84dp** 的大圆按钮，**点一下直接开录，不跳页**：

```
      ▁▂▃▅▂▁▃▂     ← 真实音量驱动的波形（无数字）
   正在听…说完点一下停止
  ⌨   ( ● 84dp )       ← 左：打字入口；中：大按钮
   本机离线识别 · 不联网，随手说
```

- 空闲：墨绿实心 + 麦克风图标 + 12dp 投影
- 录音：变红 + 停止方块 + 外圈随音量呼吸
- 转写：变回墨绿 + 环形进度

**读秒彻底去掉**：`onMillis = { /* 不读秒 */ }`，波形上方只留一句状态文字。
秒数跳字只会让人分心去数时间，对"说一句就走"没有帮助。

### 录完不用跳页

转写结果以浮层卡片回到原位：

```
┌──────────────────────────────┐
│ 听清了，是这句            ✕  │
│ 明天下午三点和张总过报价单    │
│ ┌──────┐ ┌────────────────┐ │
│ │改一下│ │     收好       │ │
│ └──────┘ └────────────────┘ │
└──────────────────────────────┘
```

「收好」直接入库；「改一下」带着文字进全屏编辑页（`vm.openCapture(seed)`）。

### 另一处体验修正：静音时说人话

以前录了 3 秒静音，提示"没听清，再说一次"—— 用户会以为自己说得不够清楚。
现在 `VoiceRecorder` 记录整段峰值音量，全程近乎静音时返回 `NoiseDetected`：

> **没听到声音**
> 检查麦克风是否被占用或被挡住，再点一次

## 四、体积与机型说明

| 版本 | 体积 | ABI | 说明 |
|---|---|---|---|
| `SuiJi-v1.0.2-release.apk` | 58 MB | arm64-v8a | 推荐；vivo X Fold3 是 arm64 |
| `SuiJi-v1.0.2-debug.apk` | 69 MB | arm64-v8a + x86_64 | 额外带模拟器架构，接电脑看日志用 |

体积从 6.8 MB 涨到 58 MB，涨的全是那 42 MB 中文模型 + 8.8 MB 识别引擎
（`libvosk.so`）。这是"不依赖任何外部服务也能转文字"的代价，我认为值得：
它把"能不能用"从厂商脸色和配置正确性里彻底解耦出来了。

> 如果你的手机不是 arm64（2016 年前的老 32 位机），这个包装不上，
> 需要改用带 `armeabi-v7a` 的构建。

## 五、想用云端（识别更准）时的正确配置

离线模型是"小模型"，日常短句够用，但专业词、长句不如云端。想用云端：

| 服务商 | 转写地址 | 转写模型 |
|---|---|---|
| 硅基流动 | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` |
| OpenAI | `https://api.openai.com/v1` | `whisper-1` |
| 自建 / 其他兼容服务 | 你的地址 | 你的模型名 |

设置 → 语音转文字 → 选「云端」→ 填这两项 → 保存。
**注意：转写地址必须单独填写**，否则程序会认为你想用当前对话服务商的地址，
而 DeepSeek 之类的地址下根本没有这个接口。

## 六、仍未解决 / 已知限制

1. **真机未复验。** 所有验证在 API 34 x86_64 模拟器上完成。vivo X Fold3 的
   OriginOS 对后台、通知、权限有额外限制，`docs/02` 末尾的 10 项真机清单仍建议照着过一遍。
2. **模拟器无麦克风输入。** UI 端只能验证到"录音启动 → 波形 → 停止 → 走离线通道"，
   真实说话时的识别效果由 instrumented test 用同一格式的音频证明了，但没在真机上"张嘴说"过。
3. **离线模型对嘈杂环境、方言、专业术语的准确率有限。** 这是 small 模型的固有上限，
   要更准请按上面第五节配云端。
4. **release 签名仍是 debug 证书**，正式上架需要换成自己的 keystore。
