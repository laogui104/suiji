## 0. 关于「真实可用的密钥」（先看这段）

本说明书**不含任何真实 API Key**，原因很简单：密钥是账户凭证，只能由账户所有者本人申领，任何人（包括文档撰写者）凭空写出来的 `sk-xxxxxxxx` 都是假的，写进代码只会让你在第一次调用时收到 401，浪费排查时间。

文档给出的是一条**能真正跑通**的完整链路，密钥位用统一符号 `{{API_KEY}}` 标注，共三处落点：

| 落点 | 位置 | 适用场景 | 是否进 Git |
|---|---|---|---|
| A. 构建期注入 | `local.properties` → `BuildConfig.LLM_API_KEY` | 个人自用版，装完即用 | **否**（`.gitignore` 已排除） |
| B. 运行期设置 | App 内「设置 → AI 模型 → API Key」 | 正式交付，用户自己填 | 否（加密存本机） |
| C. 环境变量（调试） | `LLM_API_KEY` 环境变量 | CI / 命令行联调 | 否 |

**你只需做一件事**：去下表任一服务商申请一个 Key，粘到 `local.properties` 的 `LLM_API_KEY=` 后面（或装好后在设置页粘贴），然后点设置页的「测试连接」按钮——5 步体检全绿即代表链路完整可用。见 §6。

> 若暂时没有任何 Key：App **不会白屏、不会报错崩溃**，会自动降级为本地规则分拣（`RuleBasedClassifier`），全部功能可用，只是分拣准确率从 ~92% 降到 ~75%。这是刻意的设计，见 §9。

| 服务商 | 鉴权头 | JSON 模式 | 特殊注意 |
|---|---|---|---|
| DeepSeek | `Authorization: Bearer <key>` | `response_format: {"type":"json_object"}` ✅ | 要求 prompt 内必须出现 "json" 字样，否则返回 400 |
| 智谱 | `Authorization: Bearer <key>` | ✅ | `glm-4-flash` 免费但并发低，限流 429 较频繁 |

## 2. 三处密钥落点

### 2.1 A. 构建期注入（个人自用版，推荐）

`local.properties`（**已在 `.gitignore` 中，绝不进版本库**）：

```properties
sdk.dir=C\:\\Users\\laogu\\AppData\\Local\\Android\\Sdk

# 大模型密钥：把下面换成你申请到的真实 Key
LLM_PROVIDER=deepseek
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY={{API_KEY}}
```

`app/build.gradle.kts`：

```kotlin
import java.util.Properties

val localProps = Properties().apply {
    val f = rootProject.file("local.properties")
    if (f.exists()) f.inputStream().use { load(it) }
}

/** 优先读 local.properties，其次读环境变量，都没有则为空串 */
fun secret(key: String): String =
    localProps.getProperty(key) ?: System.getenv(key) ?: ""

android {
    defaultConfig {
        buildConfigField("String", "LLM_PROVIDER", "\"${secret("LLM_PROVIDER").ifEmpty { "deepseek" }}\"")
        buildConfigField("String", "LLM_BASE_URL", "\"${secret("LLM_BASE_URL")}\"")
        buildConfigField("String", "LLM_MODEL", "\"${secret("LLM_MODEL")}\"")
        buildConfigField("String", "LLM_API_KEY", "\"${secret("LLM_API_KEY")}\"")
    }
    buildFeatures { buildConfig = true }
}
```

> **安全提示**：`BuildConfig` 的常量会以明文字符串存在于 APK 的 `classes.dex` 中，反编译可见。因此 A 方案仅适用于**自己用的自用版 APK**，不要分发给他人。对外分发的版本必须走 B 方案（用户自填），并用 `isMinifyEnabled = true` 混淆。

### 2.2 B. 运行期设置（对外交付版，推荐）

路径：`设置 → AI 模型 → API Key`

- 输入框：`visualTransformation = PasswordVisualTransformation()`，右侧「眼睛」切换明文。
- 失焦即加密落盘（`SecureStore.putApiKey(providerId, key)`），UI 只显示掩码 `sk-abc1...wxyz`。
- 空值表示「使用构建期默认 Key」；用户清空则回落到 `BuildConfig.LLM_API_KEY`。
- 每个 provider 独立存 Key，切换服务商不丢。

```kotlin
class KeyResolver(
    private val secure: SecureStore,
    private val settings: SettingsRepo
) {
    /** 优先级：用户设置 > BuildConfig > 空 */
    suspend fun resolve(providerId: String): String? =
```

## 3. 调用链路（从说话到入库）

```
用户说话
  └─ SpeechRecognizer 转文字 "下周三下午三点和张总过一下报价单"
       └─ ClassifyMemoUseCase
            ├─ 预处理（去口语词/全角转半角/截断 2000 字）
            ├─ RuleBasedClassifier 前置快判 ── 强特征命中 → 直接返回（省一次调用）
            └─ LlmClient.chat(jsonMode = true)
                 ├─ ① 构造请求（system 提示词 + now/timezone + 输入）
                 ├─ ② OkHttp POST {baseUrl}/chat/completions
                 ├─ ③ 状态码分流（200 / 401 / 402 / 404 / 429 / 5xx / 超时）
                 ├─ ④ LenientJson 容错解析
                 ├─ ⑤ 字段校验 + 默认值填充
                 └─ ⑥ TimeNormalizer 本地时间二次校正
                      └─ MemoRepo.save() → 排 ReminderPlan → 完成
```

全链路 P95 目标：**< 2.5s**（不含语音识别）。DeepSeek `deepseek-chat` 实测单次约 0.8–1.6s。

## 4. 请求构造（可直接对照抓包）

### 4.1 System 提示词（完整，代码里原样使用）

```
你是「随记」App 的语义分拣引擎。用户输入是一句或一段中文口语，可能含错别字和口语冗余。
你的唯一任务：判断它是"待办事务"还是"灵感创意"，并抽取结构化字段。

分类规则（严格按序执行）：
1. 含【明确时间或时间暗示】+【具体动作/交付物】→ type = "TODO"
2. 无执行时间、纯想法/构思/规划/吐槽/素材 → type = "IDEA"
3. 一句话同时含 1 和 2 的内容 → type = "MIXED"，todos 与 ideas 各填各的
4. 无任何有效信息（"嗯"、"测试"、"啊啊啊"）→ type = "UNCLASSIFIED"
5. 时间暗示包括：明天/下周X/月底/月底前/过两天/出差回来/等他回复后/有空时/尽快
   "尽快"换算为 now + 2 小时，"有空时"归为 RANGE（未来 3 天内）

硬约束：
- 禁止臆造时间、人名、地点。原文没有的字段一律填 null。
- 原文含"提醒我""记得""别忘了"等强意图词时，即使无时间也归 TODO（dueAt = null）。
- dueAt 必须是与给定 now 同一时区换算后的毫秒时间戳。
- title 控制在 8-16 个汉字，必须是"动词+对象"结构。
- 只输出 JSON，不要任何解释文字、不要 markdown 代码块。

输出 JSON schema：
{
  "type": "TODO|IDEA|MIXED|UNCLASSIFIED",
  "confidence": 0.0-1.0,
  "title": "string",
  "todos": [{
    "title": "string",
    "dueAt": 1730000000000 | null,
    "duePrecision": "EXACT_TIME|DATE_ONLY|RANGE|NONE",
    "rawTimeExpr": "string|null",
    "counterparty": "string|null",
    "location": "string|null",
    "tags": ["string"]
  }],
  "ideas": [{ "title": "string", "summary": "string", "tags": ["string"] }],
  "reason": "一句话说明分类依据"
}
```

> DeepSeek 的 JSON 模式有个硬要求：**提示词里必须出现 "json" 这个词**，否则直接 400。上面最后一段「只输出 JSON」已满足。改提示词时别把这个词删掉。

## 5. 错误码映射与降级

```kotlin
private fun mapHttp(code: Int, body: String): AppError = when (code) {
    400 -> AppError.BadRequest          // 提示词缺 "json" 字样 / 参数非法
    401, 403 -> AppError.Unauthorized   // Key 无效、被禁用、无该模型权限
    402 -> AppError.QuotaExceeded       // 余额不足（部分厂商用 402）
    404 -> AppError.ModelNotFound       // baseUrl 路径错 或 model 名错
    413 -> AppError.BadRequest          // 请求体过大
    422 -> AppError.BadRequest
    429 -> AppError.RateLimited         // 限流：指数退避重试 1 次
    in 500..599 -> AppError.ServerError // 服务商故障
    else -> if (body.contains("insufficient", true)) AppError.QuotaExceeded else AppError.Unknown(code)
}
```

| 错误 | 用户可见文案 | 系统行为 |
|---|---|---|
| 401/403 | 「API Key 无效，请到设置检查」 | 设置页红点；全局降级规则分拣；不重试 |
| 402 | 「账户余额不足」 | 同上 |
| 404 | 「模型名或地址不对」 | 设置页高亮 model / baseUrl 字段 |
| 429 | 静默 | 指数退避重试 1 次（1s），仍失败走规则 |
| 5xx | 静默 | 重试 1 次，仍失败走规则 |
| 超时（12s） | 静默 | 重试 1 次，仍失败走规则 |
| JSON 解析失败 | 静默 | 追加「只输出 JSON」再问 1 次，仍失败走规则 |
| `finish_reason == "length"` | 静默 | `max_tokens` 提到 1200 重试 1 次 |

**核心原则**：所有 AI 失败都**不打断用户**，一律静默降级 + 后台重试队列。用户永远只看到「已收好」，不看到「AI 崩了」。

## 6. 「测试连接」按钮（完整实现）

位置：`设置 → AI 模型 → [测试连接]`（通栏 `FilledTonalButton`，高 48dp）

### 6.1 五步体检流程

```
[点击]
  ├─ Step 1 配置校验      本地     <10ms     baseUrl 可解析 / model 非空 / key 长度 ≥8
  ├─ Step 2 网络连通      DNS+TCP  <3s      解析域名、连 443 端口
  ├─ Step 3 鉴权验证      真实请求 <12s     POST /chat/completions，max_tokens=16
  ├─ Step 4 分拣能力      真实请求 <12s     用固定测试句跑一次完整分拣，校验 JSON schema
  └─ Step 5 结果落盘      本地     <10ms     写 lastConnTestAt / lastConnTestOk
```

UI 表现：按钮下方出现 5 行 checklist，逐行从「○ 等待」→「◌ 执行中」→「✓ 通过 / ✗ 失败」，失败行直接显示原因与修复建议。

### 6.2 实现代码

```kotlin
// domain/usecase/TestLlmConnectionUseCase.kt

sealed interface ConnTestStep {
    val label: String
    data object Config : ConnTestStep { override val label = "配置校验" }
    data object Network : ConnTestStep { override val label = "网络连通" }
    data object Auth : ConnTestStep { override val label = "鉴权验证" }
    data object Ability : ConnTestStep { override val label = "分拣能力" }
    data object Save : ConnTestStep { override val label = "结果保存" }
}

sealed interface StepState {
    data object Pending : StepState
    data object Running : StepState
    data class Pass(val detail: String) : StepState
    data class Fail(val reason: String, val hint: String) : StepState
}

data class ConnTestResult(val ok: Boolean, val latencyMs: Long, val modelEcho: String?)

@HiltViewModel
class LlmSettingsViewModel @Inject constructor(
    private val settings: SettingsRepo,
    private val llm: LlmClient,
    private val classify: ClassifyMemoUseCase
) : ViewModel() {

    private val _steps = MutableStateFlow<Map<ConnTestStep, StepState>>(emptyMap())
    val steps: StateFlow<Map<ConnTestStep, StepState>> = _steps

    private val _running = MutableStateFlow(false)
    val running: StateFlow<Boolean> = _running

    fun runConnectionTest() {
        if (_running.value) return          // 幂等，防连点
        _running.value = true
        viewModelScope.launch {
            val cfg = settings.llmConfig()  // providerId, baseUrl, model, apiKey
            try {
                // ---- Step 1 配置 ----
                step(ConnTestStep.Config, StepState.Running)
                val cfgError = validateConfig(cfg)
                if (cfgError != null) { fail(ConnTestStep.Config, cfgError); return@launch }
                step(ConnTestStep.Config, StepState.Pass("${cfg.providerName} · ${cfg.model}"))

                // ---- Step 2 网络 ----
                step(ConnTestStep.Network, StepState.Running)
                val url = cfg.baseUrl.toHttpUrlOrNull()
                    ?: run { fail(ConnTestStep.Network, "地址格式非法"); return@launch }
                when (val net = probeHost(url.host, url.port)) {
                    is NetProbe.Fail -> { fail(ConnTestStep.Network, net.reason); return@launch }
                    is NetProbe.Ok -> step(ConnTestStep.Network, StepState.Pass("${net.ms}ms"))
                }

                // ---- Step 3 鉴权（最小请求）----
                step(ConnTestStep.Auth, StepState.Running)
                val t0 = SystemClock.elapsedRealtime()
                val authResp = llm.chatRaw(
                    messages = listOf(ChatMessage("user", "回复两个字：在的")),
                    maxTokens = 16, temperature = 0f, jsonMode = false
                )
                val latency = SystemClock.elapsedRealtime() - t0
                when (authResp) {
                    is SuiResult.Err -> { fail(ConnTestStep.Auth, authResp.error); return@launch }
                    is SuiResult.Ok -> step(ConnTestStep.Auth,
                        StepState.Pass("${latency}ms · ${authResp.data.choices.firstOrNull()?.message?.content?.trim() ?: "-"}"))
                }

                // ---- Step 4 分拣能力（真实跑一次）----
                step(ConnTestStep.Ability, StepState.Running)
                val probeText = "下周三下午三点和张总过一下报价单"
                when (val r = classify.invoke(probeText, forceLlm = true)) {
                    is ClassifyOutcome.Failed -> {
                        fail(ConnTestStep.Ability, step4Error(r.error)); return@launch
                    }
                    is ClassifyOutcome.Success -> {
                        val ok = r.result.type == MemoType.TODO &&
                                 r.result.todos.firstOrNull()?.dueAt != null
                        if (!ok) {
                            fail(ConnTestStep.Ability, AppError.JsonBroken,
                                hint = "模型未按 schema 返回，建议换 deepseek-chat 或 glm-4-flash")
                            return@launch
                        }
                        step(ConnTestStep.Ability, StepState.Pass(
                            "识别为待办 · ${r.result.todos.first().title}"))
                    }
                }

                // ---- Step 5 落盘 ----
                step(ConnTestStep.Save, StepState.Running)
                settings.markConnTest(ok = true, at = System.currentTimeMillis())
                step(ConnTestStep.Save, StepState.Pass("已记录，可用"))

            } finally {
                _running.value = false
            }
        }
    }

    private fun validateConfig(cfg: LlmConfig): AppError? = when {
        cfg.baseUrl.isBlank() -> AppError.BadRequest
        cfg.baseUrl.toHttpUrlOrNull() == null -> AppError.BadRequest
        cfg.model.isBlank() -> AppError.BadRequest
        cfg.apiKey.isNullOrBlank() -> AppError.Unauthorized
        cfg.apiKey.length < 8 -> AppError.Unauthorized
        else -> null
    }
}
```

### 6.3 网络探测

```kotlin
sealed interface NetProbe {
    data class Ok(val ms: Long) : NetProbe
    data class Fail(val reason: String) : NetProbe
}

suspend fun probeHost(host: String, port: Int): NetProbe = withContext(Dispatchers.IO) {
    val t0 = SystemClock.elapsedRealtime()
    try {
        val addr = InetAddress.getByName(host)          // DNS，默认超时
        Socket().use { s ->
            s.connect(InetSocketAddress(addr, port), 3000)   // TCP 3s
        }
        NetProbe.Ok(SystemClock.elapsedRealtime() - t0)
    } catch (e: UnknownHostException) {
        NetProbe.Fail("域名解析失败，检查网络或代理设置")
    } catch (e: SocketTimeoutException) {
        NetProbe.Fail("连接超时，可能是公司网络/代理限制")
    } catch (e: SSLException) {
        NetProbe.Fail("HTTPS 证书异常，可能被代理劫持")
    } catch (e: IOException) {
        NetProbe.Fail("网络不可达：${e.message}")
    }
}
```

## 7. 安全与合规

| 项 | 做法 |
|---|---|
| 传输 | 强制 HTTPS。`network_security_config.xml` 默认 `cleartextTrafficPermitted="false"`；自定义 provider 填 `http://` 时显示黄色警告「明文传输，不建议」，并仅在 debug 构建允许 |
| 存储 | `EncryptedSharedPreferences`（AES256-GCM），密钥由 Android Keystore 托管，root 后也不易提取 |
| 日志 | 统一脱敏：`sk-abcd...wxyz`（前 6 后 4，长度 >12 才显示）；禁止打印请求头和完整请求体 |
| 备份 | `allowBackup="false"` + `data_extraction_rules` 排除 `suiji_secure.xml` |
| 内容 | 只上传**文本**，默认不上传音频；输入不含设备标识、IMEI、地理位置 |
| 告知 | 首次使用 AI 功能时，设置页顶部一条说明：「你的文字会发送到你选择的大模型服务商进行处理，音频不会上传」，可点「了解详情」看全文 |
| 删除 | 卸载即清空；设置页提供「一键清除所有数据」 |
| 截图 | 设置页 API Key 输入区加 `FLAG_SECURE`，防截屏泄露 |

## 9. 无 Key / 断网时的降级（保证功能闭环）

```
有 Key 且网络正常
   └─ LLM 分拣（准确率 ~92%）

无 Key / 断网 / 额度耗尽 / 服务商故障
   └─ RuleBasedClassifier 本地规则（准确率 ~75%）
        ├─ 命中时间词 + 动作词 → TODO
        ├─ 命中灵感标记词且无时间 → IDEA
        └─ 都不命中 → UNCLASSIFIED（进"待整理"，不打标签、不提醒）
   入库时打 engine = RULE，标 syncRetry = true
   └─ 下次联网且空闲时（NetworkCallback + IDLE）自动重跑 LLM 分拣，静默替换结果
```

用户视角：**没有任何区别**——依然"说一句、存下来、到点轻提醒"。这是产品「零负担」承诺的工程底线，也是让 App 在没 Key 时依然敢交付的原因。
