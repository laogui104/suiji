### 3.1 枚举定义

```kotlin
// domain/model/Memo.kt

/** 二分类结果；UNCLASSIFIED 为兜底，进「待确认」队列，不打扰用户 */
enum class MemoType { TODO, IDEA, UNCLASSIFIED }

/** 记录生命周期；TRASHED 为软删除，保留 30 天便于回溯 */
enum class MemoStatus { ACTIVE, ARCHIVED, TRASHED }

/** 待办执行状态 */
enum class TodoStatus { PENDING, DONE, DROPPED }

/** 录入来源，用于统计与交互差异（如 WIDGET 来源不弹录音页） */
enum class CaptureSource { VOICE, TEXT, SHARE, WIDGET, TILE, LOCKSCREEN }

/** 时间精度；决定 UI 如何展示与提醒如何触发 */
enum class DuePrecision {
    EXACT_TIME,   // 2026-11-03 15:00 → 到点唤醒
    DATE_ONLY,    // 2026-11-03 → 当日空闲首窗唤醒
    RANGE,        // 本周内 / 月底前 → 区间内选最优空闲窗
    NONE          // 未识别到时间 → 不排提醒，仅入库
}

/** 灵感深化进度 */
enum class ExpandState { NONE, EXPANDING, EXPANDED, FAILED }
```

索引说明：
- `memo(createdAt)` → 时间流倒序分页
- `memo(type, status)` → 双库切换
- `reminder_log(firedAt)` → 频控窗口查询

### 4.2 DAO 关键签名

```kotlin
@Dao
interface MemoDao {

    /** 时间流：游标分页，避免 OFFSET 深翻 */
    @Query("""
        SELECT * FROM memo
        WHERE status != 'TRASHED'
          AND (:type IS NULL OR type = :type)
          AND (:cursor = 0 OR createdAt < :cursor)
        ORDER BY createdAt DESC
        LIMIT :limit
    """)
    suspend fun page(type: String?, cursor: Long, limit: Int = 30): List<MemoEntity>

    /** 带子表的完整读取（MVP 用 3 次查询在内存拼装，避免 @Relation 的 N+1） */
    @Query("SELECT * FROM todo_meta WHERE memoId IN (:ids)")
    suspend fun todoMetas(ids: List<String>): List<TodoMetaEntity>

    @Query("SELECT * FROM idea_meta WHERE memoId IN (:ids)")
    suspend fun ideaMetas(ids: List<String>): List<IdeaMetaEntity>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsert(memo: MemoEntity)

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsertTodo(meta: TodoMetaEntity)

    @Transaction
    suspend fun insertWithMeta(memo: MemoEntity, todo: TodoMetaEntity?, idea: IdeaMetaEntity?) {
        upsert(memo)
        todo?.let { upsertTodo(it) }
        idea?.let { upsertIdea(it) }
    }

    /** 到期待办扫描：每 15 分钟一次，返回进入窗口的 */
    @Query("""
        SELECT m.* FROM memo m JOIN todo_meta t ON m.id = t.memoId
        WHERE m.status = 'ACTIVE' AND t.status = 'PENDING'
          AND t.dueAt IS NOT NULL AND t.dueAt <= :now
        ORDER BY t.dueAt ASC LIMIT 50
    """)
    suspend fun dueTodos(now: Long): List<MemoEntity>

    /** 中文搜索：MVP 用 LIKE；数据量 > 5000 后切换 FTS（见 §11） */
    @Query("""
        SELECT * FROM memo
        WHERE status != 'TRASHED'
          AND (title LIKE '%' || :kw || '%' OR contentClean LIKE '%' || :kw || '%')
        ORDER BY createdAt DESC LIMIT 50
    """)
    suspend fun search(kw: String): List<MemoEntity>

### 6.1 捕获状态机

                    ┌──────────────────────────────────────────┐
                    │                  IDLE                    │
                    └────┬──────────────┬───────────┬──────────┘
      按住悬浮球/磁贴/通知    │              │ 点击"打字"  │ 系统分享
                          ▼              ▼           ▼
                    ┌──────────┐   ┌──────────┐ ┌──────────┐
                    │RECORDING │   │TEXT_INPUT│ │SHARE_ING │
                    └────┬─────┘   └────┬─────┘ └────┬─────┘
              停止/达2min │              │            │
                          ▼              ▼            ▼
                    ┌─────────────────────────────────────┐
                    │          TRANSCRIBING               │
                    └──────────────┬──────────────────────┘
                      成功          │        失败/空结果
                          ┌────────┴────────┐
                          ▼                 ▼
                    ┌──────────┐      ┌──────────┐
                    │CLASSIFYING│     │  ERROR   │──重试──┐
                    └────┬─────┘      └────┬─────┘        │
              成功        │   失败/超时      │              │
                 ┌───────┴───────┐         │              │

           ┌──────────┐   ┌──────────┐ ┌──────┐           │
           │COMMITTED │   │UNCLASSIF │ │ IDLE │◄──────────┘
           └────┬─────┘   └────┬─────┘ └──────┘
                │              │
                └──────┬───────┘

                  └──────────┘
```

关键规则：
- `RECORDING` 可被**来电、其他应用抢麦、达到 2 分钟上限、折叠屏切换**中断。中断时若已有 >1s 有效音频，自动进入 `TRANSCRIBING`，绝不丢弃；否则回 `IDLE` 并轻提示。
- `CLASSIFYING` 失败**不阻断入库**：先以 `UNCLASSIFIED` + `contentRaw` 落库（保证「不会忘」），再后台重试分拣。这是全链路最高优先级原则：**先存下来，再想明白**。
- 任一状态下退到后台，录音由 `VoiceCaptureService` 前台服务承载，UI 层销毁不影响录音。

### 6.4 语音识别双通道

```kotlin
interface SttEngine {
    /** 流式回调：partial 用于实时字幕，final 用于提交 */
    fun start(locale: Locale, onPartial: (String) -> Unit, onFinal: (String) -> Unit, onError: (AppError) -> Unit)
    fun stop()
    fun release()
}
```

| 通道 | 实现 | 优点 | 缺点 / 边界 |
|---|---|---|---|
| 系统 STT（默认） | `android.speech.SpeechRecognizer` + `RecognizerIntent` | 零成本、零 Key、离线可用性取决于厂商 | 单次时长上限约 60s，静音 5s 自动结束；部分机型需联网 |
| 云 STT（可选） | `CloudSttEngine` → 讯飞/腾讯云 一句话识别 | 长音频、准确率高 | 需额外 Key，产生费用，隐私需告知 |

默认走系统 STT，`MAX_RECORD_MS` 内分段续接：第 55 秒主动 `stopListening` 拿 final，再 `startListening` 续接，把结果拼接，规避 60s 截断。

**边界**：
- `ERROR_NO_MATCH` / `ERROR_SPEECH_TIMEOUT` → 若 `partial` 非空则用它提交；若全空 → `Error(EMPTY_SPEECH, retryable=true)`。
- `ERROR_INSUFFICIENT_PERMISSIONS` → 转文字模式。
- `ERROR_RECOGNIZER_BUSY` → 100ms 后重试 1 次。
- 转写结果 <2 字或命中噪音词表（"嗯""啊""喂""测试"）→ 判定 `NOISE`，不入库，轻提示"没听清"。

### 7.5 响应解析与 JSON 修复

模型偶尔会返回 ```json 包裹、尾逗号、前后解释文字。解析器必须容错：

```kotlin
object LenientJson {
    fun parse(raw: String): JsonObject? {
        var s = raw.trim()
        // 1) 去掉 markdown 围栏
        s = s.removePrefix("```json").removePrefix("```").removeSuffix("```").trim()
        // 2) 截取第一个 '{' 到匹配的最后一个 '}'
        val start = s.indexOf('{')
        val end = s.lastIndexOf('}')
        if (start < 0 || end <= start) return null
        s = s.substring(start, end + 1)
        // 3) 去尾逗号
        s = Regex(""",\s*([}\]])""").replace(s, "$1")
        return runCatching {
            Json.parseToJsonElement(s).jsonObject
        }.getOrNull()
    }
}
```

解析失败处理（三级）：
1. `null` → 用「重试提示」再问一次：把上次原文 + `你的输出不是合法 JSON，请只输出 JSON` 追加，最多 1 次。
2. 仍失败 → `RuleBasedClassifier` 兜底 → `engine = RULE`，`confidence = 0.4`，`needsConfirm = true`。
3. 字段缺失（如 `type` 非法）→ 逐字段给默认值，`type` 非法视为 `UNCLASSIFIED`。

     * @return 校正后的 (dueAt, duePrecision)；若与原值偏差超阈值则返回本地解析结果
     */
    fun correct(rawExpr: String?, modelValue: Long?, modelPrecision: DuePrecision, now: Long): Pair<Long?, DuePrecision>
}
```

中文时间规则表（正则 → 归一化）：

| 表达式 | 优先级 | 归一结果（now = 2026-11-01 周日 07:44） |
|---|---|---|
| `今天`/`今日` | 10 | 当日 00:00, DATE_ONLY |
| `明天`/`明早` | 10 | 2026-11-02 00:00（明早 → 08:00, EXACT_TIME） |
| `后天` | 10 | 2026-11-03 |
| `大后天` | 10 | 2026-11-04 |
| `下周X`/`下星期X` | 9 | 下一周的周 X（周一为周首，ISO 8601） |
| `这周X`/`本周X` | 9 | 本周周 X，若已过则顺延一周 |
| `N天后`/`N天之后` | 9 | now + N 日，00:00 |
| `N小时后` | 9 | now + N 小时，EXACT_TIME |
| `月底`/`月底前` | 8 | 本月最后一日 00:00 / 23:59:59 |
| `月初` | 8 | 次月 1 日 |
| `过年/春节前/国庆前` | 7 | 命中节假日表则给具体日期，否则 RANGE |
| `下午三点`/`上午10点`/`晚上八点半` | 9 | 结合当日或就近未来日，EXACT_TIME |
| `尽快`/`马上` | 6 | now + 2h, EXACT_TIME |
| `有空时`/`回头`/`看情况` | 5 | now..now+3d, RANGE |
| `等他回复后`/`出差回来` | 4 | dueAt = null, DATE_ONLY（不排提醒，靠闲时补提） |

**校正策略**：若 `modelValue` 与 `本地解析值` 相差 > 24h，且本地命中优先级 ≥ 8 的强规则 → 采用本地值并记 `WARN` 日志（`rawExpr` 便于回归）。若本地无命中 → 信任模型值。

**边界**：
- 时间早于 `now - 5min`（如"昨天说的明天"）→ 不排提醒，`duePrecision` 降为 `NONE`，并打标 `OVERDUE_ON_ARRIVAL`，在列表中显示"已过期"分组。
- 跨年：`12月31日` 提到时若已过，顺延到明年。
- 时区：存储时固化 `dueTz`，用户改时区不重算已有待办（避免出差后全体错乱）。

## 8. 闲时判定引擎（对应 3.3 前置）

### 8.1 设计原则

「不打扰」不是把音量关掉，而是**在用户不方便的每一刻都闭嘴**。因此判定必须是保守的：宁可今天不提醒，也不能在开会时弹一下。

### 8.2 信号采集 `IdleDetector`

```kotlin
class IdleDetector(
    private val ctx: Context,
    private val usageStats: UsageStatsReader,
    private val motion: MotionTracker
) {
    fun snapshot(): IdleSignals
}
```

| 信号 | 采集方式 | 需要权限 | 无权限时降级 |
|---|---|---|---|
| `screenOn` | `PowerManager.isInteractive` | 无 | — |
| `keyguardLocked` | `KeyguardManager.isKeyguardLocked` | 无 | — |
| `msSinceScreenOn` | 监听 `ACTION_SCREEN_ON` 存时间戳 | 无 | — |
| `msSinceLastInteraction` | `UsageStatsManager.queryEvents` 最近 `MOVE_TO_FOREGROUND`/`SCREEN_INTERACTIVE` | `PACKAGE_USAGE_STATS`（用户手动开） | 用 `msSinceScreenOn` 近似 |
| `msSinceSignificantMotion` | `Sensor.TYPE_SIGNIFICANT_MOTION` 一次性传感器，触发后重新挂 | 无 | 视为 0（保守，不判空闲） |
| `foregroundCategory` | `UsageStatsManager.queryUsageStats` 取最近前台包名 → 分类表 | `PACKAGE_USAGE_STATS` | `UNKNOWN`（按中性处理） |
| `audioMode` | `AudioManager.mode` | 无 | — |

**娱乐类应用判定**：`AppCategory` 用内置包名映射表（抖音/快手/B站/微博/小红书/王者荣耀/和平精英/爱奇艺/腾讯视频/优酷/YouTube）。**不申请 `QUERY_ALL_PACKAGES`**——该权限在 Google Play 属敏感权限，且用 `UsageStatsManager` 拿到的包名做 map 查表即可，无需枚举全部应用。

### 8.3 打分算法

```kotlin
object IdleScorer {
    fun assess(s: IdleSignals, cfg: IdleConfig, now: Long): IdleAssessment {
        // 一票否决：任何硬阻断直接 BLOCKED，score = 0
        if (s.withinQuietHours) return blocked("QUIET_HOURS")
        if (s.audioMode == AudioManager.MODE_IN_CALL ||
            s.audioMode == AudioManager.MODE_IN_COMMUNICATION) return blocked("IN_CALL")
        if (s.dndFilter != NotificationManager.INTERRUPTION_FILTER_ALL) return blocked("DND_ON")
        if (!s.screenOn) return blocked("SCREEN_OFF")

        var score = 0
        // 1) 屏幕亮起后持续时长（权重 30）：越久越可能空闲
        score += when {
            s.msSinceScreenOn > 10 * 60_000 -> 30
            s.msSinceScreenOn > 3 * 60_000  -> 22
            s.msSinceScreenOn > 60_000      -> 10
            else -> 0
        }
        // 2) 无操作时长（权重 35）：静置是空闲的最强信号
        score += when {
            s.msSinceLastInteraction > AppConfig.IDLE_MIN_DURATION_MS * 4 -> 35
            s.msSinceLastInteraction > AppConfig.IDLE_MIN_DURATION_MS     -> 25
            s.msSinceLastInteraction > 30_000                            -> 12
            else -> 0
        }
        // 3) 运动状态（权重 15）：手机被持续拿起晃动 → 正在忙
        score += when {
            s.msSinceSignificantMotion > 5 * 60_000 -> 15
            s.msSinceSignificantMotion > 60_000     -> 8
            else -> 0
        }
        // 4) 前台应用类别（权重 20）：娱乐类说明在放松，正是"间隙空档"
        score += when (s.foregroundCategory) {
            AppCategory.ENTERTAINMENT -> 20
            AppCategory.SOCIAL        -> 14
            AppCategory.SYSTEM        -> 12   // 桌面/设置
            AppCategory.IM            -> 6    // 在聊天，谨慎
            AppCategory.WORK          -> 0    // 在工作，绝不打
            AppCategory.UNKNOWN       -> 4
        }
        // 5) 充电中（权重 5）：通常在家/工位，适合轻提醒
        if (s.charging) score += 5

        // 迟滞：避免 69/71 反复跳变
        val state = when {
            score >= cfg.threshold            -> IdleState.IDLE
            score >= cfg.threshold - 30       -> IdleState.SEMI_IDLE
            else                              -> IdleState.ACTIVE
        }
        return IdleAssessment(state, score, buildReasons(s, score))
    }
}
```

阈值默认 70。设置页「闲时敏感度」滑块把阈值映射到 60（更易触发）~85（更克制）。用户**只能调得更保守或更宽松 15 分**，不能关闭硬阻断项（夜间/通话/免打扰）。

### 8.4 评估调度

```
WorkManager PeriodicWork (15min, flex 5min)
   └─ IdleWatchWorker
        ├─ assess()
        ├─ if IDLE && 有 PENDING_IDLE 待办 && 全局频控通过
        │     └─ DispatchReminderUseCase → 显示顶部条 / 系统通知
        └─ 写 ReminderLog(reasonsSnapshot)
```

**为什么用 WorkManager 而不是 AlarmManager 常驻轮询**：WorkManager 周期任务对电量友好，且系统会在 Doze 下批量唤醒；精确到分钟的实时性对"柔性提醒"无价值——晚 15 分钟提醒，比打扰用户 100 次好。

### 8.5 边界

| 场景 | 处理 |
|---|---|
| 息屏 | `BLOCKED`。息屏提醒必然亮屏，属强打扰。**唯一例外**：`dueAt` 已超过 `windowEnd` 仍未提醒过，则在下次解锁瞬间（`ACTION_USER_PRESENT`）补一次 |
| 用户从未授权 `PACKAGE_USAGE_STATS` | 走降级链路：仅用屏幕时长 + 静置 + 运动。此时 `threshold` 自动 +10（更保守） |
| 用户在打游戏（前台 WORK/游戏） | `foregroundCategory` 需把游戏单独归 `ENTERTAINMENT`，但游戏全屏沉浸时若有 `WindowInsets` 全屏信号则降为 `ACTIVE`（避免打断团战）。MVP 先用「游戏包名 → ACTIVE」白名单 |
| 系统时间被改 | 全用 `elapsedRealtime()` 算时长，`currentTimeMillis()` 只用于展示与 dueAt 比较 |
| 折叠屏展开瞬间 | 不触发评估（10s 防抖），避免刚展开就弹条 |

## 9. 柔性提醒引擎（对应 3.3）

### 9.1 三层节奏

```
T-0   dueAt 到达            → ReminderWorker 把 plan.status = PENDING_IDLE（不打扰）
T+X   下一个空闲窗口         → DispatchReminderUseCase 判定通过后 SHOWN
T+Y   用户忽略               → 45 分钟后若仍空闲且 remindCount < 2，再补一次
T+3d  仍未唤醒               → EXPIRED，进列表"逾期"分组，不再提醒
```

核心：**dueAt 只是"可以开始提"的起点，不是"必须此刻弹"的指令。** 这是与所有传统待办 App 的根本差异。

### 9.2 调度实现

```kotlin
class ReminderScheduler @Inject constructor(
    private val wm: WorkManager,
    private val alarm: AlarmManager,
    private val ctx: Context
) {
    /** dueAt 到点只做一次轻唤醒，把状态推进到 PENDING_IDLE */
    fun arm(plan: ReminderPlan) {
        val req = OneTimeWorkRequestBuilder<ReminderWorker>()
            .setInitialDelay(max(0, plan.dueAt - System.currentTimeMillis()), MILLISECONDS)
            .setConstraints(Constraints.NONE)   // 不要求联网，本地判定即可
            .addTag("reminder_${plan.memoId}")
            .build()
        wm.enqueueUniqueWork("rem_${plan.memoId}", REPLACE, req)
    }

    /** 精确闹钟（可选）：用户开启"准时唤醒"时才用，需 SCHEDULE_EXACT_ALARM */
    fun armExact(plan: ReminderPlan)
}
```

`ReminderWorker.doWork()`：

```
plan = repo.planOf(memoId)
if (plan == null || plan.status != SCHEDULED) return success
if (now > plan.windowEnd) { markExpired(); return success }
repo.setPlanStatus(memoId, PENDING_IDLE)
IdleWatchWorker.triggerNow(ctx)   // 立即触发一次空闲评估，别等 15 分钟
```

### 9.3 派发决策 `DispatchReminderUseCase`

```kotlin
suspend fun dispatch(now: Long): DispatchResult {
    if (!settings.reminderEnabled.first()) return Skipped("DISABLED")
    val assessment = assessIdle()
    if (assessment.state != IdleState.IDLE) return Skipped("NOT_IDLE:${assessment.reasons}")

    // 全局频控：距上次任一提醒 < 45min 则跳过（防轰炸）
    val lastAny = logDao.lastFiredAt() ?: 0
    if (now - lastAny < AppConfig.MIN_GAP_BETWEEN_ANY_MS) return Skipped("GLOBAL_COOLDOWN")

    val candidates = repo.pendingIdlePlans(now).filter { plan ->
        val meta = repo.todo(plan.memoId) ?: return@filter false
        meta.remindCount < plan.maxFires &&
        (meta.lastRemindAt == null || now - meta.lastRemindAt!! >= plan.minGapMs)
    }
    if (candidates.isEmpty()) return Skipped("NO_CANDIDATE")

    // 排序：先到期先提；同日则按 priority 降序；再按创建时间
    val target = candidates.sortedWith(compareBy({ it.dueAt }, { -priorityOf(it) }, { it.memoId })).first()
    return Fire(target)
}
```

### 9.4 提醒形态

| 表面 | 条件 | 实现 | 参数 |
|---|---|---|---|
| **应用内顶部条**（主） | App 在前台 | `InlineReminderBar` 组合项，`AnimatedVisibility` 从顶部滑入 | 高 40dp，圆角 12dp，背景 `surfaceVariant` @ 12% alpha，文字 `bodySmall` / `onSurfaceVariant`，无图标无按钮 |
| 系统通知（兜底） | App 不在前台 | `NotificationCompat`，channel `suiji_soft` | `IMPORTANCE_LOW`、`setSilent(true)`、`setSound(null)`、`enableVibration(false)`、`setOnlyAlertOnce(true)`、`priority = PRIORITY_LOW`、`category = CATEGORY_REMINDER` |
| 全局悬浮条（可选） | 用户单独授权 `SYSTEM_ALERT_WINDOW` 且开启「锁屏也提醒」 | `WindowManager` + `TYPE_APPLICATION_OVERLAY` | 不获取焦点 `FLAG_NOT_FOCUSABLE`，宽 `MATCH_PARENT`，高 40dp，`y = 状态栏下方 8dp` |

**绝对不做**：`IMPORTANCE_HIGH`、`setFullScreenIntent`、`Vibrator`、`RingtoneManager`、全屏 Activity、`Toast` 循环。代码层面用 lint 自定义规则或 `detekt` 规则禁掉这几个 API 出现（见 §15.3）。

`IMPORTANCE_LOW` 的物理意义：不发出声音、不产生 heads-up 悬浮、不在状态栏显示图标（只在通知栏折叠区）——正是"顶部淡色小字"的诉求。

### 9.5 交互规则（顶部条）

```

停留 4000ms
   ├─ 用户点击 → 展开详情页（不打断，只在原位盖一层半透明卡片，返回即回原位）
   ├─ 用户右滑 → DISMISS，记 log，本条不再提醒
   ├─ 用户左滑 → SNOOZE 2h
   └─ 超时 → 自动收起为右侧一个小圆点(8dp, 30% alpha)，点击可再展开

- 同一时刻**最多显示 1 条**。若队列里还有，收起后间隔 ≥30s 再出下一条。
- 用户正在录音 / 正在输入 / 正在灵感深化页 → 挂起，等这些状态结束再出。
- 折叠屏悬停态时，顶部条显示在上半屏顶部（下半屏为操作区，不遮挡）。

### 9.7 边界

| 场景 | 处理 |
|---|---|
| 用户连续忽略 3 条 | 自动把「闲时敏感度」阈值 +5（更克制），并在设置页提示"已为你降低提醒频率" |

| 提醒时用户正在看同一条详情 | 不提醒，标记 `ALREADY_VIEWING` |
| dueAt 在夜间 22:00-07:30 到期 | 不立即派发，顺延至 07:30 后首个空闲窗口 |

## 11. 归档、搜索与回溯（对应 3.5）

### 11.1 列表分组规则

时间流按「自然时间桶」分组，标题只显示相对词：

```
今天 · 3
昨天 · 1
本周 · 5
更早
```

待办额外按状态加视觉分层：`逾期`（红色小圆点，仅 1 个像素级提示，不弹窗）> `今天` > `本周` > `无时间`。

### 11.2 搜索

MVP：`LIKE '%kw%'`，覆盖 `title` + `contentClean`，限制 50 条。
搜索交互：首页顶部下拉出现搜索框（不占常驻空间）。输入即搜，debounce 250ms。

数据量 > 5000 条时切换到 FTS：

```sql
CREATE VIRTUAL TABLE memo_fts USING fts4(
  title, contentClean, tokenize=unicode61
);
```
中文分词问题：`unicode61` 对连续汉字按整串切分，导致单字搜不到。方案：写入时额外生成 bigram 串（"会议纪要" → "会议 议纪 纪要"）存入 `contentBigram` 列，FTS 建在该列上，查询时同样 bigram 化。此方案纯 SQLite 实现，无需引入分词库，索引体积约为原文 2 倍。

### 11.3 回收站

- 删除 = `status = TRASHED` + `deletedAt = now`。
- 首页 → 设置 → 回收站 可查看，30 天后 `CleanupWorker` 物理删除。
- 「事不会忘」意味着删除必须可撤销：删除后 5 秒内底部出现 `Snackbar：「已移除 · 撤销」`。

### 13.3 「测试连接」按钮（需求明确要求）

按钮位置：设置页「AI 模型」分组内，通栏 `FilledTonalButton`，高 48dp。

点击后进入 5 步体检，每步实时打勾，总耗时不超过 15s：

```kotlin
class TestLlmConnectionUseCase(
    private val llm: LlmClient,
    private val settings: SettingsRepo
) {
    fun run(): Flow<ConnTestStep>
}

sealed interface ConnTestStep {
    data object CheckConfig : ConnTestStep                // 1 配置完整性
    data object CheckNetwork : ConnTestStep               // 2 网络连通（DNS + TCP）
    data object CheckAuth : ConnTestStep                  // 3 鉴权（最小请求）
    data class CheckJson(val ok: Boolean) : ConnTestStep  // 4 JSON 模式可用性
    data class Done(val ok: Boolean, val latencyMs: Long, val modelEcho: String?, val error: AppError?) : ConnTestStep
}
```

**Step 1 配置校验**
- `baseUrl` 非空且能被 `HttpUrl.parse` 解析
- `model` 非空
- `apiKey` 长度 ≥ 8
- 任一失败 → 直接 `Done(ok=false, error=配置错误)`，并高亮出错字段。

**Step 2 网络**
- `InetAddress.getByName(host)` 超时 3s → DNS 失败提示「域名解析失败，检查网络或代理」
- 对 `host:443` 建 TCP 连接超时 3s → 提示「网络不通，可能是公司网络/代理限制」

**Step 3 鉴权 + 真实生成**（一步完成，省流量）
```json
POST {baseUrl}/chat/completions
{
  "model": "<model>",
  "messages": [{"role":"user","content":"回复两个字：在的"}],
  "max_tokens": 16,
  "temperature": 0,
  "stream": false
}
```
响应映射表：

| HTTP | 判定 | 提示文案 |
|---|---|---|
| 200 | 鉴权通过 | 记录 `latencyMs` 与 `choices[0].message.content` |
| 401 / 403 | Key 无效或权限不足 | 「API Key 无效或已被禁用」 |
| 402 | 余额不足 | 「账户余额不足，请充值」 |
| 404 | 路径或模型不存在 | 「接口路径或模型名不存在，请检查 base_url 与 model」 |
| 413 | 输入过长 | 不太可能出现，兜底「请求体过大」 |
| 429 | 限流 | 「请求过于频繁，稍后再试（不影响实际使用）」 |
| 500/502/503 | 服务端异常 | 「模型服务商异常，非本地问题」 |
| 超时 | 网络慢 | 「连接超时 12s，检查网络或换服务商」 |
| `UnknownHostException` | DNS | 「域名解析失败」 |
| `SSLHandshakeException` | 证书 | 「HTTPS 证书异常，可能是代理劫持」 |

**Step 4 JSON 模式**
- 若预设 `supportsJsonMode`，发一次真实分拣请求（用固定测试句「下周三下午三点和张总过一下报价单」），校验返回能被 `LenientJson` 解析且 `type` 合法。
- 通过 → 显示「分拣引擎就绪」，并回显解析出的 type 与 dueAt，让用户**亲眼看到链路是通的**。
- 若 provider 不支持 json mode，跳过此步，标「该服务商不支持 JSON 模式，已用提示词约束」。

**Step 5 结果落盘**
- 写 `lastConnTestAt` / `lastConnTestOk`，设置页「连接状态」行显示 `✓ 正常 320ms` 或 `✗ 失败：API Key 无效`。
- 失败时提供「查看诊断详情」可展开原始响应（Key 已脱敏）。

**安全**：测试请求不写入任何用户真实内容；日志只记状态码与耗时，不记请求头。

## 15. 边界与异常处理矩阵

### 15.1 输入侧

| 场景 | 处理 | 用户可见反馈 |
|---|---|---|
| 空输入 | 不提交 | 按钮禁用 |
| 纯噪音（嗯/啊/测试） | 不入库 | 顶部轻提示「没听清」 |
| 超长 > 2000 字 | 截断 + 保留全文入库，仅前 2000 字送模型 | 无感 |
| 一句话含 3 个事务 | `MIXED`，拆 3 条 todo，共享同一 `contentRaw` | 列表显示 3 张卡，来源折叠为一条 |
| 中英混说 | 照常送模型，提示词已声明可混 | — |
| 方言/口音识别错 | 规则兜底可能误判，`confidence < 0.55` 时进「待确认」 | 卡片右上角显示「?」小标记，点击选待办/灵感 |
| 表情/纯符号 | 判定 UNCLASSIFIED | 存原文，不出现在主时间流，进「待整理」 |
| 重复录入同一句 | 24h 内 `contentRaw` 相似度 > 0.9 时提示「这条好像记过」 | 可继续保存或查看原条 |

### 15.2 网络 / 服务侧

| 场景 | 处理 |
|---|---|
| 无网 | 跳过 LLM，`RuleBasedClassifier` 兜底，`engine = RULE`，入 `retryQueue` |
| 弱网超时 | 重试 1 次（指数退避 500ms），仍失败则规则兜底 |
| Key 失效 | 设置页红点提示，全局降级为规则分类，不阻塞任何功能 |
| 额度耗尽 | 同上，且顶部一次性说明条「AI 分拣已暂停，当前使用本地规则」 |
| 服务商返回 HTML（代理错误页） | `LenientJson` 失败 → 规则兜底 |
| 响应被截断（`finish_reason = "length"`） | 提高 max_tokens 重试 1 次 |
| 用户切后台时提交完成 | 不弹任何东西，仅写 log；下次打开在列表可见 |

### 15.3 平台 / 系统侧

| 场景 | 处理 |
|---|---|
| Android 13+ 未给通知权限 | 提醒降级为仅应用内，设置页显示"去开启" |
| 国产 ROM 杀后台（vivo/小米/华为） | 首次启动后第 2 天，若检测到 WorkManager 任务被漏执行，弹一条极简引导（不是对话框，是列表顶部条）跳设置 |
| 精确闹钟权限被收回（Android 14） | `canScheduleExactAlarms()` 返回 false → 自动改用 `setAndAllowWhileIdle` 非精确模式，功能不降级 |
| 麦克风被其他 App 占用 | 提示后转文字 |
| 系统时间跳变 | 所有时长用 `elapsedRealtime`，dueAt 比较用墙钟 |
| 用户卸载重装 | 数据全在本地 Room，随应用删除；引导页提示先导出备份 |
| 折痕/悬停导致 Activity 重建 | 已用 `configChanges` 规避；若仍断言重建，`ViewModel` + `SavedStateHandle` 兜底恢复 |

### 15.4 代码级禁令（Code Review Checklist）

1. 禁止在 `Composable` 里直接调用 `System.currentTimeMillis()` 做业务判断——统一走注入的 `Clock`，便于测试。
2. 禁止任何 `IMPORTANCE_HIGH` 通知、`setFullScreenIntent`、`Vibrator.vibrate`（除录音开始的 1 次触感）、`RingtoneManager`。
3. 禁止在日志中打印 `contentRaw`（用户隐私）与 API Key。
4. 禁止 `runBlocking` 出现在主线程调用链。
5. 禁止硬编码屏幕宽度 dp 判断，必须走 `WindowSizeClass` + `FoldingFeature`。
6. 禁止新增第 6 个页面。新增页面前先证明它不能以 sheet / 面板形式存在。
